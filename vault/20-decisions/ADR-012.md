## Context

Three questions arrived together while specifying REQ-WP-004.

**Where does the book live?** The reconstruction written for REQ-WP-003 sits in
`src/channelflow/connectors/binance/orderbook.py`, but nothing in it is
Binance-specific: it takes normalized `BookDelta` and `BookSnapshot` values and
applies PRD §11.1's procedure. A second venue would have to import it from a
module named after the first.

**Who fetches the rebuild snapshot?** PRD §11.1 step 5 says to mark the book
stale and rebuild. Rebuilding means a REST call.

**How is staleness measured?** PRD §11.1's `BookHealth` requires `latency_ms`
and `stale_ms`. Both are naturally read from a clock. Constitution Principle I
forbids look-ahead and Principle VII requires live and replay to be the same
code; a book whose staleness came from `time.time()` would report different
health replaying the same recorded stream twice.

## Decision

1. **The book moves to `src/channelflow/book/`.** It keeps its
   `# @trace: REQ-WP-003` marker — the code did not change hands, only
   location — and gains `# @trace: REQ-WP-004` for what this feature adds.
   Binance-specific parsing stays in the connector.
2. **The service performs no I/O.** On a gap it becomes invalid and *asks* for
   a snapshot; the caller supplies one to `rebuild`. The service never fetches.
3. **Staleness is event-time arithmetic.** `health(as_of_ns=...)` returns the
   difference between the caller's event time and the last applied event time.
   No module in the feature imports a clock, asserted over the source the way
   the bar builder and the backtest already are.

## Consequences

- **Principle VIII gets its shape.** "Connectors share one interface" only
  means something if the thing behind the interface is not inside one
  connector.
- **The test suite needs no network and no fake HTTP.** A rebuild is a method
  call with a snapshot argument. Recorded streams and live streams follow the
  same path — Principle VII, obtained by construction rather than by discipline.
- **The caller carries the retry policy, and that is the right place for it.**
  How long to wait before re-requesting a snapshot, how many times, and what to
  do when the venue keeps failing are operational questions with no correct
  answer inside a data structure.
- **`latency_ms` as PRD §11.1 names it is not reported.** Latency is the gap
  between exchange time and ingest time, which is a property of the connector's
  transport, not of the reconstruction. Reporting it here would require this
  module to know when it received something — the exact dependency this ADR
  removes. It belongs with the connector's error metrics (WP-003, PRD §33.2).
- Moving the module changes an import path for REQ-WP-003's tests. That is the
  cost, and it is paid once.
