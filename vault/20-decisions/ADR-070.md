## Context

Nine of the page's lower panes read "no data" because nothing produces the data behind them: the ingest
subscribes to trades only, and no process stores a derivatives state, a liquidation, a book or a quote. The
pure code that would consume them exists and is tested; what is missing is a *place* for the producers to live
and a *rule* for how what they collect becomes a feature.

Two facts about the running system constrain that place. The worker is a batch pass of 28-35 minutes that
reads whole tables and writes `feature_snapshots` with a watermark per series. And Iceberg tables here commit
by optimistic concurrency: two processes appending to one table can make one of them fail its commit.

## Decision

**1. A new service, `context`, one process per venue, collects raw observations.** Not the ingest: the ingest
is one process per symbol on the trade path and its job is the bars; a book or a REST poll that misbehaves must
not be able to stall the bars, and the bars' replay-parity story ([[REQ-NRT-PARITY]]) should not acquire a
second kind of input. Not the worker: it runs in batches and these sources are continuous (a book minute cannot
be reconstructed half an hour later from a socket).

**2. The collector writes append-only raw tables** -- `derivatives_state`, `liquidations`, `book_minutes`,
and the existing `quotes` -- and **computes no feature**.

**3. The worker is the only writer of `feature_snapshots`** and gains one pass that, for every series and every
timeframe with bars, evaluates each context feature **as of the bar's close** from observations with
`event_time <= close`, using the library functions that already exist and carry their own refusals. Rationale:
one writer avoids the commit conflict; one place computes features, so replay and live cannot differ; the
point-in-time rule is enforced where it can be tested (a feature at `t` is unchanged when later rows appear).

**4. Top-of-book streams, sampled and summarised per minute in event time.** Binance's partial-depth stream and
OKX's `books5` are snapshots: each frame is a whole top of book, so there is no delta chain to reconstruct.
Bybit's linear book is a first snapshot followed by deltas; the existing `BookService` handles that (it is
tested for gaps and resnapshot) and is read once a second, so every venue's OFI is computed from the same
1 Hz sampling. OKX's `books5` carries five levels, so its depth imbalance is over five and is written under the
ten-level name only where a venue's book really has ten per side. The
collector finalises each minute from the frames before its boundary and stores a summary (OFI, depth
imbalance, quote, frame count). The raw book is **not archived**: at 100-1000 ms across five markets it is the
largest data in the system and nothing in the requirements needs it. The consequence is stated, not hidden: for
these features replay parity means "the stored summaries produce the stored features", not "the socket can be
replayed". The trade path keeps its raw archive.

**5. Staleness is a per-feature parameter, set where it is used.** The library's 5-minute default is right for
a polled open interest and wrong for funding, whose *settlement* is an 8-hour event; with the default,
`funding_z` would exist for five minutes in eight hours. The writer passes the bound explicitly and the choice
is recorded beside it.

**6. A spot series is given its own venue's perpetual for derivatives.** The Binance series are spot markets; the
derivatives are the same venue's perpetual of the same pair, and the association is stated in the registration
and the docs. A pane may not silently show a perpetual's number under a spot instrument's name.

**7. Deployment is incremental.** The collectors are new services started with `docker compose up -d --no-deps`;
the worker image is rebuilt only after the pass has been run against the real lakehouse on throw-away ports
without writing, because a rebuild deploys everything committed since the last build, not only the new work (the
lesson of 2026-10-08).

## Consequences

**Three more tables and a service make three more things that can fail**; each has a health signal and a
metric for the age of its last write, and a pane whose collector is down goes back to "no data" with the reason
("nothing written since ..."), which is the honest degradation.

**Small Iceberg files.** A row a minute per symbol per table is exactly the workload that makes a snapshot
chain long; the sinks buffer and the maintenance service compacts and expires them like every other table.

**The sampling limit on OFI is permanent in this design**: it is computed from sampled snapshots. An
event-level OFI needs the delta stream and the reconstruction §11.1 describes; that is a later choice, and the
feature's registration says what it measures today.

**Host load is a real cost** on a machine that also runs the live stack and other projects; the collectors'
CPU is measured before and after and the stream interval is chosen to fit.
