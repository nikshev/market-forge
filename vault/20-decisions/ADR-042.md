## Context

REQ-WP-019's fifth acceptance criterion, quoted from the PRD: the "derivative
experiment can return `NO_EDGE` without blocking product completion".

That sentence is about coupling, not about an enum. A research experiment that
signals its result by raising makes every caller decide what to do about a
finding, and the safe thing a caller does with an unexpected exception is stop.
The product would then be blocked by the discovery that a hypothesis did not pay
off — which is the ordinary outcome of a hypothesis.

PRD §13A.11's own "critical limitation" section lists seven reasons a derivative
root is not sufficient evidence. Not finding an edge is the expected case.

## Decision

**Every research conclusion is a returned `ExperimentOutcome`.** Too little
data, no root, no root that survives §13A.12's gate, no improvement on the
no-skill base rate — all four return the same shape, carrying a verdict, a
reason, the comparison report and the stability metrics.

**A mistake in the call still raises.** A feature the rows do not carry, a row
with no forward path: those are findings about the code. Returning `NO_EDGE` for
them would dress a bug up as a fact about the market, and the experiment would
report an absence of edge that it never actually looked for.

## Consequences

- **The verdict is checkable.** `NO_EDGE` carries the report it was based on, so
  a reader can disagree with it rather than take it.
- **The distinction has a test.** A missing feature raises; a signal-free dataset
  returns. Without the second test, catching everything would look identical.
- **`EDGE` requires both halves**: at least one promoted root *and* beating the
  base rate. A promoted root whose predictions do not beat the base rate is a
  root that survived a stability gate and predicted nothing.
- **Nothing forces a caller to read the reason.** The verdict is an enum and a
  caller may branch on it alone. That is acceptable here: the failure mode of
  ignoring the reason is a less-informed decision, not a false one.
