## Context

REQ-WP-019's acceptance, quoted from the PRD:

1. future-bar invariance test passes;
2. confirmation legality test passes;
3. replay parity passes;
4. **direct baseline metrics exist**;
5. **derivative experiment can return `NO_EDGE` without blocking product
   completion**.

The first three are §13A.28's Tests A, C and E, and this feature delivers them.

The fourth needs §13A.13's direct supervised targets — `P(local_max_within_H)`
and the rest — which need labelled point-in-time data, which is REQ-WP-017. The
fifth needs §13A.11's GMDH derivative hypothesis, which is REQ-WP-018.

Neither is built. Neither can be: Constitution Principle IV states that no ML
or GMDH layer is added until deterministic baselines exist and leakage tests
pass — and the deterministic baseline is precisely what this feature is.

## Decision

**REQ-WP-019 advances to `tested` and stops there.** It does not reach
`implemented`, because two of the five conditions the PRD sets for it are
unmet.

The five `REQ-NRT-*` constraints this feature does satisfy — A, B, C, D and E —
reach `implemented` on their own, since each is a single testable property and
each now has a test.

## Consequences

- **The dashboard will show a work package stuck below `implemented`, and that
  is the correct reading.** PRD §13A is an engine, not a component; its work
  package spans a structural baseline, an ML baseline and a GMDH experiment.
  Marking it implemented because the first third works would make the
  traceability graph say something false.
- **Five hard-gated constraints move off `draft` for the first time.** R5 has
  never been able to fire on them because nothing produced them a test; they
  have sat at `draft` since extraction. This is the work that gives them one.
- **REQ-NRT-F stays at `draft`.** It tests GMDH derivative root stability and
  there is no GMDH. It advances with REQ-WP-018.
- **Nothing in the tooling enforces this.** No validator rule says "a
  requirement may not be marked implemented while its acceptance is unmet" —
  that judgement is human, and this ADR is the record of making it. Which is
  also the honest reading of `CLAUDE.md`'s own note that the status ladder is
  a discipline the commands follow, not a gate the tooling enforces.
- Reversible: when REQ-WP-017 and REQ-WP-018 land, WP-019's remaining two
  criteria can be met and its status advanced without touching this code.
