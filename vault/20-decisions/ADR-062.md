## Context

[[ADR-059]] decided that deleting is a capability the table layer is never
handed. `ObjectStore` had no `delete`; retention would take a
`PrunableObjectStore` that extended it with one; `Table`, `back_up`, `restore`
and `verify` would keep the narrower port and stay structurally unable to remove
anything. The protection was a type error rather than a code review.

[[ADR-060]] then replaced that port. The plane is Iceberg, and Iceberg's own
`FileIO` carries `delete` beside the `new_input` and `new_output` every read and
write already uses. There is no narrower port to hold, and `IcebergTable` has to
expose its handle so backup can walk manifests and metadata.

So the guarantee [[ADR-059]] bought is gone. The question is what replaces it,
and the first answer to reject is "nothing, because it is obvious that only
retention deletes". Nothing announced is nothing enforced, and a "clean up the
failed commit" branch is a natural thing to reach for.

## Decision

**Only `retention.py` may call `delete` on a `FileIO`, and a test asserts it.**

The test reads the source of every module under `channelflow/` and fails if any
but `retention.py` calls `.delete(` on an IO object. It is the same shape as the
import checks `tests/unit/lakehouse/test_isolation.py` already runs for PRD
§29.0's layering rule.

## Consequences

This is **weaker** than what it replaces, and recording it as weaker is the
point. A signature cannot be worked around by accident; a test can be worked
around by anyone who edits it, and it fires after the code is written rather
than while it is being written.

It is also stronger than the alternative on offer. A convention nobody checks
survives exactly as long as everyone remembers it, and the cost of forgetting
here is data removed by a path that was never reviewed as a removal.

The trade came from [[ADR-060]] and was not visible when that decision was made:
adopting a format means adopting its capability surface, and Iceberg's is wider
than the port it replaced. That is worth naming as a general cost of the
migration rather than a quirk of this rule — the format's conveniences arrive
together with its sharp edges, and the sharp edges do not come with our
opinions attached.

If a narrower seam is ever wanted, it would be a wrapper over `FileIO` that
forwards reads and refuses deletes, handed to everything except retention. That
is a real option and it costs a wrapper on the hottest path in the system, which
is why it is not taken today.
