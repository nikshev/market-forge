## Context

Thirty-six outcome notes and five ADRs in this vault cite a mutation sweep.
[[ADR-047]] credits one with finding a quantile band that was never enforced.
Phrases like "23 of 23 caught" are the evidence on which requirements moved to
`implemented`.

**None of it was reproducible.** Every sweep ran from a throwaway script, retyped
per requirement and never committed. So a flaw in one was a flaw in all of them,
a fix in one fixed nothing else, and nobody but the author could re-run a sweep
or check a number.

Two flaws proved that concretely, one found and one that was always available:

- **Python validates its bytecode cache on `(mtime, size)`.** Two consecutive
  mutants producing files of identical size within one second reuse the first's
  `.pyc`, so the second run executes the first's code and reports its result.
  Found on 2026-09-12. It cost work in the direction it happened to fall; the
  other direction turns a survivor into a reported catch and shows nothing.
- **No script checked that the suite was green before mutating.** Against a red
  suite every mutant is "caught" and the sweep reports a perfect score for a test
  file that does not run. Never hit, always one broken import away.

A third appeared while converting the sweeps into files, and is the most
instructive: **a mutation that breaks the module is not a catch.** The first
conversion lost the leading indentation of every multi-line pattern, because
TOML's basic multi-line string treats a trailing backslash as a line
continuation that also eats the next line's whitespace. Those mutations produced
unparseable code, the suite went red without running, and every one was scored
as caught. The most emphatic possible result, meaning nothing.

## Decision

**`tools/mutate.py` plus `tests/mutations/*.toml`.** One specification per
module, patterns as TOML *literal* strings, run by `make mutate`.

The tool refuses a red baseline; disables the bytecode cache; requires each
pattern to match exactly once; parses the mutated source before running anything;
treats a collection error as a broken mutation rather than a catch; counts a hang
as caught; and restores the source in a `finally`.

**A survivor must carry a recorded reason, and a survivor that starts being
caught is a failure.** Every sweep here has ended with a handful of survivors and
a paragraph explaining why each is acceptable — an unreachable branch, a guard a
later guard covers, a contract comment that could not be reproduced. Those
paragraphs are the accumulated understanding of the module, and until now nothing
checked them. Making a now-caught survivor fail turns each one into an assertion
with a date on it.

**It runs in CI.** 151 mutations in 251 seconds, about 1.7 seconds each.

## Consequences

**The numbers are now other people's too.** `make mutate` reproduces every figure
in the vault: 141 caught, 10 survived, across six specifications. Confirmed
against what was reported per module — Slipstream 23/0, Aerodrome family 4/0,
Curve Stableswap-NG 34/1, Cryptoswap 32/8, Uniswap v4 25/0, HyperCore 27/1.

**The cost grows with coverage.** Roughly 1.7 seconds per mutation, and every new
requirement adds twenty to forty. The trigger for revisiting this is the sweep
taking longer than the rest of the gate; at that point the options are running it
only on changed specifications, or moving it out of CI and back to a deliberate
audit. Recording the trigger is the point — it is a measured decision now and
should be re-measured, not re-argued.

**The cheap half runs on every commit.** A test loads every specification and
checks each pattern still matches its source exactly once and still parses. A
drifted pattern is then found in milliseconds on the fast gate rather than after
a full suite run each in CI.

**What this does not do is generate mutations.** They are written by hand, one
per way the module could plausibly be wrong, which is the part that needs
judgement. An off-the-shelf mutation engine would enumerate far more and mean far
less: the value here has always been in choosing mutations that correspond to
mistakes a person would actually make.
