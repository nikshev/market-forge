id: ADR-064
title: A pinned tag is only as durable as its registry
status: accepted
decides: [REQ-INFRA-002]
date: 2026-09-12

## Context

CI went red on a commit that changed no infrastructure:

    docker: Error response from daemon: pull access denied for minio/minio,
    repository does not exist or may require 'docker login'

The image is pinned to an explicit release, `RELEASE.2025-09-07T16-13-09Z`, not
`latest`, exactly as Principle XI requires. The tag had not moved. **The
repository was gone**: Docker Hub's API answers `object not found` for
`minio/minio` outright.

MinIO's community images now live on quay.io, where both of this project's
pinned releases are present — `quay.io/minio/minio:RELEASE.2025-09-07T16-13-09Z`
and `quay.io/minio/mc:RELEASE.2025-08-13T08-35-41Z`, the same immutable release
names, verified by pulling both.

`specs/002-project-bootstrap/research.md` rejected digest pinning at bootstrap
and left a condition for revisiting it: *"Revisit if a patch release ever breaks
the stack."* That condition has now been met by something the condition did not
anticipate, and this ADR is the revisit.

## Decision

**Change the registry, keep the tags.** `docker-compose.yml` and
`.github/workflows/ci.yml` name `quay.io/minio/*` at the same releases.

**Do not adopt digest pinning in response to this.** It would not have helped: a
digest is resolved through a registry too, and `sha256:...` against a repository
Docker Hub no longer serves fails the same way, with a worse error. The
bootstrap note's reasoning against digests — that they turn routine patch
upgrades into a manual lookup — is untouched by what happened.

## Consequences

**The reproducibility risk that materialised is not tag mutation.** Principle XI
is about a checkout resolving to the same stack later, and the bootstrap work
read that as "do not say `latest`", which is necessary and, it turns out, not
sufficient. The dependency is on a *registry continuing to serve a name*, and no
form of pinning addresses that. Only mirroring would, and mirroring two
containers for a development stack costs more than it buys.

**So this will happen again**, to some image, and the response is the same three
steps: find where the project moved its images, confirm the pinned release is
there, change the registry. Writing that down is the whole value here — the
twenty minutes this cost went to establishing that the failure was not in the
commit that surfaced it.

**A red CI on an unrelated commit is worth reading before assuming.** The commit
under test added a Curve quote adapter with no infrastructure change at all. A
habit of re-running or of suspecting the diff first would have wasted more.
