## Context

R8 requires a requirement at `implemented` to have at least one source file
carrying its `# @trace:` marker. It was found in the field: `REQ-WP-010` was
marked implemented, sixteen tests verified it, and no source file claimed it —
the whole request-to-implementation half of its graph was missing and
`validate` reported clean.

The rule was written for work packages, and until 2026-09-09 no phase had ever
left `draft`, so the case never arose. It arose when `REQ-PHASE-6`'s last two
deliverables closed and the note was promoted: R8 fired, because no module
implements a phase. A module implements a work package that delivers part of
one.

Under the direct reading that is not a phase failing to earn `implemented` — it
is `implemented` being unreachable for an entire requirement type, permanently.
The `covers:`/`not_delivered:` machinery added the same day exists to make a
phase's status promotable, and R8 made the top rung unreachable regardless of
what was built.

## Decision

**`covers:` becomes an edge, and R8 follows it.**

`collect_requirements` emits a `COVERS` edge per entry, which puts the
relationship in the graph rather than in frontmatter only. Two things follow
without further work: R3 catches a misspelled covering id — and a typo in a
coverage claim reads exactly like coverage — and R8 can ask the question a
roll-up can answer.

A requirement has code when a source file carries its marker, **or** when it
covers at least one requirement and *every* one of them has code.

Three parts of that are deliberate:

- **`all`, not `any`.** A phase half of whose covering work has no traceable
  code has no traceable code either. `any` would pass it on the strength of the
  half that is built, which turns a transitive rule into a partial one.
- **`at least one`.** A phase covering nothing has no code, which is the right
  answer for one — PRD §45's Phase 8 covers nothing today, and an empty
  `covers:` standing in for code would let it claim to be implemented.
- **One hop, not a walk.** A phase covers work packages, and work packages carry
  markers. Nothing here covers a coverer, and a general transitive closure would
  invent a relationship the vault does not have.

## Consequences

- **`REQ-PHASE-6` is the first phase at `implemented`**, and R8 still means what
  it meant: implemented means code exists, reachable from the requirement.
- **The rule was changed while it was blocking a status I wanted**, which is the
  shape of a bad decision, so the reasoning has to stand without that. It does:
  R8 made a rung unreachable for a requirement type rather than unearned, and a
  ladder with a rung nothing can reach is a defect whether or not anyone is
  standing under it. The alternative — putting `# @trace: REQ-PHASE-6` in a
  source file — would have been a marker no module means.
- **Four mutations cover the new behaviour**, including the `any`/`all` reading
  and the empty-`covers:` case, because both are the ways this could quietly
  become an exemption.
- **`test_phase_coverage.py` is now the second gate on a phase's status**, and
  the two ask different questions: R8 asks whether the covering work has code,
  and the coverage test asks whether the covering work is `implemented` and the
  gap list is empty.
