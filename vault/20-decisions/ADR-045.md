## Context

[[ADR-020]] settled what a mangled deep link does with PRD §27.5's channel mode:
anything that is not exactly `false` means `AS-SEEN-THEN`, because "a value
mangled in transit must not silently become a refit".

§27.2's overlay list raises the same question with an extra case. A mode is one
token — readable or not. A list of twelve can arrive *partly* readable: three
names this build knows and one it does not.

Restoring the three looks like success. The chart draws layers, the page says
nothing, and the one layer that went missing is the one the reader cannot see
was ever there. If that layer was the volume profile or the liquidation levels,
the setup on screen is not the setup the alert was about.

## Decision

**Any unrecognised name discards the whole list**, and the page falls back to a
declared default set with a notice saying the alert's own layers could not be
restored.

There are three states, and the page distinguishes them:

- **restored** — the link named layers and all were understood; nothing is said,
  because nothing is wrong;
- **not recorded** — no parameter at all, which every alert sent before this
  feature carries; the defaults are drawn and the page says the alert did not
  record them;
- **unreadable** — the parameter was there and could not be trusted; the same
  defaults, and the page says so in different words.

An **empty** parameter is none of those three: `overlays=` means the alert
recorded that no layers were on, and that is restored exactly. Falling back to
the defaults there would overrule a recorded fact with a guess.

A **duplicated** name is drawn once. A repeat is sloppy rather than corrupt, and
discarding a perfectly readable state over one would lose more than it protects.

## Consequences

- **A reader is never guessing whether the chart matches the alert.** The two
  fallback states are visible, in words, above the chart.
- **Adding a layer to the vocabulary is a two-sided change.** `Overlay` in
  Python and `OVERLAYS` in TypeScript are the same twelve strings, and a rename
  on one side turns every link into the unreadable state. Both files carry a
  comment saying so; nothing enforces it, which is a gap worth a test if a third
  consumer ever appears.
- **Old links keep working**, and are honest about what they are: an alert from
  before this feature lands in "not recorded" rather than silently claiming a
  restoration.
