## Context

PRD §9 opens with "Every event must include" and then gives `EventMeta` with
eight fields: `source`, `venue`, `market_type`, `symbol`, `event_time_ns`,
`ingest_time_ns`, `sequence`, `source_event_id`.

PRD §10's seven canonical models do not include it. They repeat `venue`,
`symbol` and `event_time_ns` as flat fields and omit the other five entirely —
including `ingest_time_ns`, which §9's own rule set distinguishes from
`event_time` and which §0.4 lists among the timestamps that must never be
conflated.

Separately, §10 is inconsistent about numeric types. `TradeEvent` uses `Decimal`
for `price`, `qty_base` and `notional_quote`; `DexSwapEvent` uses `Decimal` for
amounts and price; the extremum models in §13A.19 use `Decimal` for prices. But
`DerivativesState` uses `float` for `mark_price` and `index_price`, and
`LiquidationEvent` uses `float` for `price`, `qty` and `notional_usd`.

## Decision

**Every canonical event embeds `meta: EventMeta`** rather than flattening its
fields. The duplicated `venue`, `symbol` and `event_time_ns` are removed from the
seven models in §10; access becomes `trade.meta.venue`.

**Every monetary quantity is `Decimal`.** `mark_price`, `index_price` and the
liquidation `price`, `qty` and `notional_usd` become `Decimal`. `float` is kept
only for genuinely dimensionless derived ratios — `funding_rate`, `basis_bps`,
`open_interest_base`, `open_interest_usd` — where a rounding error is not a
correctness failure and the value is itself an estimate.

## Consequences

- **The contradiction in §9 versus §10 is resolved in favour of §9**, which
  states a rule ("every event must include"), against §10, which shows examples.
  A rule beats an illustration when they disagree.
- **`ingest_time_ns` and `sequence` become impossible to omit.** Under the flat
  reading, an event could be constructed without them and nothing would object.
  Since §9's own rule forbids any feature depending on `ingest_time` as market
  information, the field has to exist before that rule can be checked at all.
- **A price cannot silently lose precision.** A mark price at `float` is a price
  in exactly the same sense as a trade price; the PRD treats them differently
  with no stated reason, and that reads as inconsistency rather than intent.
  Principle XI (results reproducible) and §0.14 (correctness before performance)
  both point the same way.
- **Storage schemas are unaffected.** PRD §29's tables pin partitioning and order
  keys, not Python types, and §29.0 already requires backend specifics to live
  behind adapters. A flat storage row can be produced from a nested model.
- **Deviation from the PRD's literal text is recorded here.** The PRD is
  read-only and still says what it says. Anyone reading §10 and finding the
  implementation different should find this ADR first.
- Reversible: flattening `meta` later is mechanical, and widening `Decimal` to
  `float` loses nothing. Going the other way — recovering precision already
  discarded — is not possible, which is why the stricter choice is made now.
