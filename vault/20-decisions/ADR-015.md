## Context

PRD §19 opens "Every feature definition must be registered" and lists sixteen
required fields — name, version, family, description, formula, units, required
source events, lookback, update cadence, availability lag, null policy,
clipping, normalization, point-in-time safety, test fixture. Its worked example
is `ofi_5s`, a feature this work package produces.

Constitution Principle VI ends: "An undocumented feature is not done."
REQ-PRIN-008 restates it and has been sitting at `draft` since extraction,
with no work package to attach to — because until now nothing produced a
feature.

The channel quality submetrics of REQ-WP-006 are the closest prior case, and
they are not registered. They predate any registry.

## Decision

**REQ-WP-011 builds the registry**, registers its own features in it, and the
spec traces REQ-PRIN-008 as well as REQ-WP-011.

**The registry is enforced by a test, not by convention**: the set of features
the package exposes and the set of registered names must be equal, and no
required field may be blank. Adding a feature without registering it fails the
suite by name.

## Consequences

- **A registry added later would be a documentation exercise.** Written
  alongside the first features it is a gate: the failure mode it prevents —
  a number in a signal that nobody can define — happens at the moment the
  feature is written, not at the moment someone gets round to documenting it.
- **REQ-PRIN-008 gets a home.** It can advance past `draft` because there is
  now code that satisfies it and a test that verifies it. It is `type:
  constraint` but not `hard_gated`, so R5 does not force this; the reason to do
  it is that the principle is otherwise unfalsifiable.
- **REQ-WP-006's quality submetrics are left unregistered, deliberately.**
  Backfilling them would mean re-opening a merged requirement to satisfy a
  rule that did not exist when it shipped. The registry covers what this
  package exposes; extending it to the channel features is its own small piece
  of work, and this ADR is the record that it is owed.
- **Sixteen fields per feature is heavy, and that is the intent.** A feature
  whose availability lag or null policy nobody can state is a feature nobody
  should be trading on. The cost falls at write time, which is when the author
  still knows the answers.
- Reversible in the sense that entries are data; the test that enforces
  completeness is what makes it more than a comment.
