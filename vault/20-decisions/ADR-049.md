## Context

EXP-001 lists seven metrics by name and defines none of them:

> next-H coverage; boundary interaction stability; number of false "perfect"
> historical touches; slope stability; width stability; computational cost;
> rejection strategy expectancy OOS.

Five of them have an obvious reading. Two did not.

**"Number of false 'perfect' historical touches"** is the experiment's own name
for a repaint symptom, and there are two ways to count it: bars the *current*
channel calls a perfect touch that the channel of the time did not, or bars
whose touch classification changed at any point between. The first is what a
person looking at a chart sees — a history full of bars that kissed the boundary
exactly, none of which did so when they happened.

**"Computational cost"** invites a stopwatch. A stopwatch reading is not
reproducible: it varies with the machine, the load and the run, and a report
that cannot be compared with itself cannot be compared with another. Principle
XI is not negotiable for a research report whose whole purpose is comparison.

## Decision

**A false perfect touch is a bar the last fit calls a boundary touch and the fit
of the time did not.** Counted against the most recent channel, because that is
the one a chart draws.

**Computational cost is a deterministic operation count**: the dominant term of
one fit times the number of fits — `n` for the least-squares and Kalman models,
`n × iterations` for the reweighted Huber fit, `3 × n(n−1)/2` for the quantile
enumeration. It ranks the models the way a stopwatch would and returns the same
number twice.

The other five are defined in the docstrings of the functions computing them,
each stated so a reader can disagree with the definition rather than with a
number.

## Consequences

- **The cost figure is a ranking, not a duration.** It says the quantile fit
  costs two orders of magnitude more than the least-squares one per fit, which is
  the decision it exists to inform; it does not say how many milliseconds.
- **It has to be updated when an algorithm changes.** A constant in a table that
  drifts from the code it describes is a real risk, and the test that separates
  the expensive model from the cheap one is what would catch a table saying they
  cost the same.
- **The touch definition depends on a band width**, set at 2% of the channel and
  held equal across models. A different width changes every model's count in the
  same direction, which is why the comparison survives the choice.
- **Coverage looks forward and is measured against the band as it stood.** A
  channel projected along its slope would be the richer measure and needs the raw
  log slope, which `ChannelSnapshot` does not carry; PRD §13.7's forecast channel
  is where that belongs.
