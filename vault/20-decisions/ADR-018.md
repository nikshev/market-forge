## Context

PRD §26.4 asks for retry with exponential backoff, a dead-letter table, a
delivery audit, and — the load-bearing line — "never block signal engine on
Telegram failure".

The obvious implementation opens an HTTP session, sleeps between retries and
reads the wall clock for its audit timestamps. Each of those is a problem here:

- an HTTP client makes every test either networked or mocked at the socket;
- `sleep` makes the retry test as slow as the backoff it is testing;
- a wall-clock timestamp makes a replayed stream produce a different audit,
  breaking Principle VII.

[[ADR-012]] settled the same three questions for the order book.

## Decision

1. **The transport is supplied by the caller** — a protocol with one method.
   The package contains no HTTP client and no credential.
2. **Backoff is computed, not slept.** The policy maps an attempt number to a
   delay; waiting is the caller's, as is the decision to wait at all.
3. **Audit timestamps are event times**, passed in. No module reads a clock.
4. **Queueing never raises.** A transport failure becomes an audit record, not
   an exception travelling back into the signal engine.

## Consequences

- **"Never block the signal engine" becomes a property rather than a promise.**
  There is no call in the queue path that can block: no socket, no sleep. A
  test asserts that queueing survives a transport that always throws.
- **The retry test runs in microseconds** and asserts the delays are increasing,
  which is the actual requirement. A test that slept would assert the same thing
  and take a minute.
- **Credentials cannot leak from a module that has none.** The token lives in
  the caller's environment, and `.env.example` carries a placeholder.
- **The caller now owns the scheduling loop**, which is real work this package
  does not do. That is the honest split: retry *policy* is a decision with a
  right answer, retry *timing* is an operational concern that depends on how
  the process is run.
- **A real Telegram transport is still owed**, and will be a small adapter
  under the connector boundary rather than a change here.
