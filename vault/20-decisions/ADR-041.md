title: Root stability is assessed over a deterministic lattice, not a bootstrap

## Context

PRD §13A.12 condition 3 asks that a "derivative root is stable across
bootstrap/ensemble members", and Test F (§13A.28) requires that "small
perturbations within a configured tolerance must not create silently unstable
promoted roots".

A bootstrap answers this by resampling. Resampling needs a random source, and a
random source needs a seed — at which point the stability metric depends on a
number nobody chose for a reason, and two runs of the same assessment can
disagree about whether a root is stable.

Constitution Principle XI requires reproducible results. A metric that is itself
unstable cannot support the sentence "this root is stable": it is the same
instability one level up.

## Decision

**Members come from a deterministic lattice.** Each of the path's coefficients
is scaled by `1 - tolerance`, `1`, and `1 + tolerance`, and every combination is
a member — 27 of them for a cubic. The set is exhaustive rather than sampled, so
the assessment is a function of the path and the tolerance and nothing else.

A tolerance of zero is refused: it perturbs nothing, so every member is the
original path and the presence rate is 1 by construction — a stability check
that cannot fail.

A coefficient that is exactly zero is left alone. Zero there is a statement
about the path's degree — a quadratic is not a cubic with a small cubic term —
and scaling it up from nothing would perturb the shape rather than the estimate.

## Consequences

- **The same path and tolerance assess identically, always**, and a test asserts
  it. Principle XI holds for the stability metric itself, not only for the
  prediction it guards.
- **The lattice grows as `3^k`.** With four coefficients that is 81 at worst,
  which is cheap. A path family with many more terms would need a different
  scheme, and this ADR would be revisited rather than quietly sampled.
- **§13A.12 says "bootstrap/ensemble", and this is the ensemble reading.** The
  section's own numbers — presence rate, horizon IQR, turn-type agreement — are
  computed the same way over either.
- **The tolerance stays the caller's.** It is the "configured tolerance" Test F
  names, and it belongs to the instrument, not to this module.
