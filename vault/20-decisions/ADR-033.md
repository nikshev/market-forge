## Context

PRD §18.4 rule 5: "A reorg cannot silently mutate an existing signal snapshot;
emit an invalidation/correction event instead." PRD §41 rule 6 is the same rule
from the research side: "No using later corrected/reconstructed DEX state as if
known earlier unless audit semantics explicitly allow it."

The obvious implementation deletes the orphaned records, or updates them in
place with the corrected data. Both are wrong for the same reason, and it is
not obvious until you consider a backtest.

A strategy running at 12:00 acted on a swap in block B. At 12:05 block B was
reorganised out. A backtest replayed tomorrow, over corrected data, will never
see that swap — so it will never make the decision the live system made, and
the two will disagree in a way that looks like the strategy improving.

The record of what was known at 12:00 has to survive the correction, because it
is what actually drove the decision.

## Decision

**A reorg emits an invalidation record and stamps the original with
`orphaned_at`.** The original's other fields are never touched, and it is never
deleted.

**A read as of an instant before the reorg still returns it.** It was genuinely
what was known then, and a point-in-time read that hid it would be
reconstructing history rather than reporting it.

**A reorg claiming to remove a finalized block is refused**, since finality is
the claim that this cannot happen — a chain that contradicts it is a bug or an
attack, and either way not something to absorb silently.

## Consequences

- **Replay parity survives a reorg.** Principle VII requires live and replay to
  be the same code over the same data; this makes "the same data" true after
  the chain changes its mind.
- **The audit trail is the storage.** PRD §41 rule 6's escape clause — "unless
  audit semantics explicitly allow it" — is satisfied by keeping both the
  original and the invalidation, so a consumer can ask either question and get
  the honest answer to each.
- **Downstream materializations must handle invalidation explicitly**, which is
  §18.4 rule 4's requirement and is now visible rather than implicit. A
  consumer that ignores invalidations will drift, and it will do so loudly at
  the next reconciliation rather than quietly at read time.
- **Records accumulate.** An orphaned record is kept forever; on a chain with
  frequent shallow reorgs that is real storage. The alternative is losing the
  ability to answer what was known at a past instant, which is the whole point.
