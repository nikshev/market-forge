## Context

PRD §16.2 gives a four-quadrant interpretation of price and open interest
moving together:

```text
price up + OI up     => new risk entering / trend participation candidate
price up + OI down   => short-covering candidate
price down + OI up   => new shorts / risk build candidate
price down + OI down => long liquidation/de-risk candidate
```

and then, in the same breath: "Interpretation matrix stored as feature, not
hard-coded trading truth."

That sentence is unusual in the PRD. Most sections specify what to compute;
this one specifies what *not* to conclude. It is there because the matrix is
folklore that happens to be plausible — every quadrant has a story, the stories
are memorable, and none of them has been tested here.

## Decision

**The regime is a labelled value and nothing else.** No module in this package
branches on it, weights anything by it, or feeds it into a decision. Its
registry entry records it as a categorical feature with no established
directional meaning.

The four names come from the PRD verbatim, including the word "candidate" in
each, which is the PRD hedging its own matrix.

## Consequences

- **A model may learn from it, and that is the legitimate use.** The regime is
  a compact encoding of a two-variable joint direction; whether it predicts
  anything is a question for REQ-WP-017's dataset and the walk-forward
  evaluation, not for a feature module.
- **A signal rule branching on the regime would encode folklore as a
  threshold**, and it would be invisible: the rule would look like domain
  knowledge and behave like a guess. Principle IV's "no model until baselines
  pass leakage tests" is about the same failure at a larger scale.
- **The names carry their hedge.** Keeping "candidate" in each label is a small
  thing that survives copy-paste into a dashboard, where "new shorts" alone
  would read as a fact.
- Reversible: if the matrix earns its keep in evaluation, acting on it becomes
  a signal-engine decision with evidence behind it.
