title: The frontend is gated in CI, not in the pre-commit hook

## Context

REQ-WP-009 is the first requirement whose implementation is largely TypeScript.
Until now the fast gate (pre-commit) and the full gate (CI) have both been
Python-only.

`CLAUDE.md` states the rule that keeps the split honest: **no check may be
absent from both gates.** So the frontend's type check, lint and tests must run
somewhere, and the question is where.

Running `npm ci` in the pre-commit hook would add tens of seconds to every
commit — including commits that touch no frontend file, which will be most of
them — and would make committing depend on a Node toolchain being installed.
REQ-INFRA-002's whole reason for existing is that the fast gate must not
require services or heavy setup.

## Decision

**The frontend is checked in CI only**: `tsc --noEmit`, the frontend tests, and
the production build all run in the full gate. The pre-commit hook stays
Python-only.

`make web-typecheck`, `make web-test` and `make web-build` exist so the same
commands run locally and in CI, exactly as the Python targets do.

## Consequences

- **A broken frontend can be committed and will be caught on push.** That is
  the same bargain REQ-INFRA-002 already made for integration tests, and it is
  stated rather than discovered.
- **`make` remains the single interface.** CI calls the same targets a
  developer calls, so the two cannot drift — the property the two-gate design
  exists to preserve.
- **CI gets slower and gains a Node setup step.** Acceptable: it runs on push,
  not on every commit, and it is the gate that decides whether `implemented`
  was earned.
- **The rule is honoured, narrowly.** Every frontend check runs in exactly one
  gate. If someone later removes a step from the CI workflow, nothing else
  will catch it — which is precisely what `CLAUDE.md` says to check before
  removing anything from either gate.
